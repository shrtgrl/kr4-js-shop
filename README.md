# Контрольная работа №4

Тема: «JavaScript: интерактивность, DOM, события, формы и валидация».

## Описание

**HeartBeat** — учебный интернет-магазин виниловых пластинок. В рамках КР №4 в него добавляется интерактивность на чистом JavaScript (без React, Vue и сторонних библиотек).

## Основа проекта

Проект `kr4-js-shop` создан как отдельный репозиторий на основе адаптивной версии интернет-магазина из **контрольной работы №3** (`kr3-responsive-shop`).

Из КР №3 перенесены:

- 5 страниц: главная, каталог, карточка товара, заявка, контакты;
- адаптивная вёрстка (Mobile First, `responsive.css`);
- доступность: skip-link, видимый фокус, `aria-*`, модальное окно на `<dialog>`;
- бургер-меню и сворачиваемый фильтр каталога.

Тематика изменена: вместо учебного магазина — магазин виниловых пластинок HeartBeat. Фотографии футбольных форм удалены; на финальном этапе добавлены фото пластинок и новый дизайн (см. раздел «Оформление»).

## JavaScript-файлы

- `data.js` — массив товаров `products` (11 пластинок, жанры `hiphop`, `rock`, `rnb`, `pop`), словарь названий жанров `CATEGORY_LABELS` и список фото для главного экрана `HERO_IMAGES`.
- `cart.js` — корзина: хранение в `localStorage`, добавление, изменение количества, удаление, расчёт суммы через `reduce`, промокод, счётчик в шапке, вывод страницы `cart.html`. Здесь же общие функции цены (`formatPrice`, `calculateDiscount`, `calculateFinalPrice`), которые используют каталог, корзина и форма.
- `catalog.js` — вывод карточек, поиск, фильтрация и сортировка, кнопки «В корзину», случайные пластинки на главной.
- `product.js` — страница товара по `id` из адреса.
- `validation.js` — валидация формы заявки, блок «Ваш заказ», имитация отправки.
- `main.js` — общая инициализация проекта: бургер-меню, кнопка фильтров каталога, случайное фото на главном экране.
- `theme.js` — переключение и сохранение тёмной темы.

Порядок подключения на страницах: `theme.js` (без `defer`) → `data.js` → `cart.js` → `catalog.js` → `product.js` / `validation.js` → `main.js`. Каждый следующий файл использует данные и функции предыдущих.

### Корзина (`cart.html`, `js/cart.js`)

- Кнопка «В корзину» в каталоге добавляет пластинку; повторное нажатие увеличивает количество. Кнопка на 1,2 с показывает «Добавлено ✓».
- В корзине хранятся только `id` и количество: `[{ id: 2, quantity: 2 }]`. Название, цена и скидка берутся из `products`, поэтому в корзине не остаются устаревшие данные.
- На странице корзины для каждой пластинки есть кнопки `−` / `+` и «Удалить»; при уменьшении количества до нуля пластинка удаляется. Кнопка «Очистить корзину» удаляет всё.
- Строки корзины создаются через `createElement` и `textContent`; кнопки обрабатываются одним обработчиком на списке (делегирование, `data-action`).
- У кнопок `−`, `+` и «Удалить» есть `aria-label` с названием пластинки.
- Если корзина пуста, показывается сообщение со ссылкой в каталог.

### Расчёт суммы через `reduce`

- `getCartCount()` — общее количество пластинок.
- `getCartTotal()` — сумма с учётом скидок товаров: `цена со скидкой × количество` для каждой строки.
- Пример: Nevermind × 2 (4 050 руб.) + Abbey Road (3 840 руб.) = 11 940 руб.

### Сохранение в `localStorage`

- Корзина хранится под ключом `heartbeat-cart`, применённый промокод — под ключом `heartbeat-promo`.
- Массив сохраняется через `JSON.stringify` и читается через `JSON.parse`.
- Чтение обёрнуто в `try/catch` и проверку `Array.isArray`: если данные повреждены, корзина начинается пустой, а скрипт не падает.

### Промокод

- Доступные коды: `HEARTBEAT10` (−10 %) и `VINYL15` (−15 %), хранятся в объекте `PROMO_CODES`.
- Ввод нормализуется через `trim().toUpperCase()`, поэтому `vinyl15` тоже работает.
- Проверка через `Object.hasOwn`, чтобы ввод вроде `toString` не считался промокодом.
- Скидка промокода выводится отдельной строкой, итог пересчитывается сразу.

### Счётчик товаров в шапке

- В меню всех страниц есть ссылка «Корзина» со счётчиком; счётчик обновляется при каждом изменении корзины и скрыт, когда корзина пуста.

### Форма заявки

- Над формой выводится блок «Ваш заказ» со списком пластинок из корзины и итоговой суммой с промокодом.
- Список пластинок в поле «Товар» строится из массива `products`; товары не в наличии недоступны для выбора.
- Добавлена проверка согласия на обработку персональных данных.
- Имитация отправки: кнопка блокируется и показывает «Отправляем…», через 1,5 с выводится сообщение с номером заявки, форма, корзина и промокод очищаются. Повторная отправка во время ожидания невозможна.
- Данные заявки (контакты, пластинки, промокод, сумма) собираются в объект и выводятся в консоль.

### Тёмная тема (`js/theme.js`)

- В шапке всех страниц есть кнопка-переключатель ☾ / ☀ с `aria-pressed` и `aria-label`.
- Тема включается атрибутом `data-theme="dark"` на теге `<html>`; в CSS для `:root[data-theme="dark"]` переопределены только значения цветовых переменных — сами стили не дублируются.
- Добавлена переменная `--color-on-primary` (цвет текста на основном цвете): в светлой теме белый текст на синем, в тёмной — тёмный текст на светло-голубом, чтобы сохранить контраст.
- `color-scheme: dark` переключает в тёмный вид поля ввода, списки и чекбоксы браузера.
- Выбор сохраняется в `localStorage` (ключ `heartbeat-theme`); при первом визите тема берётся из настроек системы через `matchMedia('(prefers-color-scheme: dark)')`.
- `theme.js` подключается в `<head>` первым и без `defer`: тема применяется до отрисовки страницы, поэтому нет белой вспышки при переходах. Кнопка подключается после события `DOMContentLoaded`.

### Страница товара по `id` (`product.html`, `js/product.js`)

- В каждой карточке каталога есть ссылка «Подробнее» вида `product.html?id=6`.

## Принцип безопасного вывода данных

Для вывода данных используется `textContent`, а не `innerHTML`.

`innerHTML` разбирает строку как HTML-разметку. Если строка пришла от пользователя (из формы, `localStorage` или API), в ней может оказаться, например, `<img src=x onerror=alert(1)>` — браузер создаст элемент и выполнит чужой код (XSS-атака).

`textContent` всегда вставляет строку как обычный текст, поэтому любые теги просто отображаются символами. Этот опыт показан в `js/main.js` (этап 13) и оставлен закомментированным.

## Почему `defer` и порядок скриптов

```html
<!-- catalog.html -->
<script src="js/data.js" defer></script>
<script src="js/cart.js" defer></script>
<script src="js/catalog.js" defer></script>
<script src="js/main.js" defer></script>
```

- `defer` — скрипт загружается параллельно с HTML и выполняется после разбора страницы, поэтому `querySelector` находит элементы;
- скрипты с `defer` выполняются в порядке подключения: сначала `data.js` создаёт данные, затем `catalog.js` и `validation.js` их используют;
- обычные (не модульные) скрипты делят глобальную область видимости, поэтому `catalog.js` и `validation.js` видят массив `products` из `data.js`.
